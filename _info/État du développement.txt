RESTRUCTURATION DES DOSSIERS (2026-09-08)
--------------------------------------------
Passage d'une organisation PAR TYPE (scripts/, scenes/, resources/) à une
organisation PAR FEATURE. Voir "Structure Projet Claude-Godot.txt" pour
l'arborescence cible complète et les raisons du changement.

Fait :
- scripts/entities/player/*.gd, scenes/player/Player.tscn et
  resources/data/player_movement_config.tres → fusionnés dans entities/player/
- scripts/core/*.gd → renommé core/ (reste par type, car générique/partagé,
  pas une feature — voir doc de structure)
- Déplacement fait depuis le dock FileSystem de l'éditeur (pas l'explorateur
  Windows) pour préserver les références — vérifié après coup, rien de cassé
- Style guide : espace avant les ":" de type hint corrigé (ex.
  "var speed : float" -> "var speed: float") dans core/state_machine.gd,
  core/movement_config.gd, entities/player/walk_state.gd


PHASE 1 — MOUVEMENT + ATTAQUE
================================

[FAIT] Mouvement top-down + FSM Idle/Walk — testé et fonctionnel en éditeur

Détails techniques de ce qui est en place :

1. Player.tscn
   - Racine : CharacterBody2D (renommé "Player")
   - Enfants : AnimatedSprite2D, CollisionShape2D
   - Enfant StateMachine (Node, script state_machine.gd)
	 - Enfant Idle (Node, script idle_state.gd)
	 - Enfant Walk (Node, script walk_state.gd)
   - Les noms "Idle" et "Walk" doivent rester exacts (utilisés comme clés de
	 dictionnaire dans state_machine.gd)

2. Pattern State générique (réutilisable, pas juste pour Player)
   - core/state.gd → class_name State
	 Interface : enter(actor), exit(), physics_update(delta, actor),
	 handle_input(event, actor) — toutes vides/virtuelles dans la base
   - core/state_machine.gd → class_name StateMachine
	 - @export var actor: CharacterBody2D (assigné dans l'Inspecteur avec le
       noeud Player)
     - states: Dictionary rempli dans _ready() à partir des enfants
     - _physics_process délègue à current_state.physics_update()
     - transition_to(state_name) : exit() → swap current_state → enter()
   - Les états concrets accèdent à leur StateMachine parente via
     (get_parent() as StateMachine) — jugé sécuritaire car les states sont
	 garantis d'être des enfants directs d'une StateMachine par construction

3. États concrets du Player
   - entities/player/idle_state.gd
   - entities/player/walk_state.gd
   - Emplacement (depuis la restructuration du 2026-09-08) :
     entities/player/ pour tout ce qui est spécifique au Player (états,
     scène, données) ; core/ réservé au générique/partagé entre features.

4. Vitesse en data-driven (pattern Resource du doc original, pas hardcodé)
   - core/movement_config.gd → class_name MovementConfig,
     @export var speed: float = 200.0
   - entities/player/player_movement_config.tres → instance de données
   - WalkState a @export var config: MovementConfig, assigné dans
	 l'Inspecteur avec le fichier .tres ci-dessus
   - Convention (depuis la restructuration) : scripts de classe Resource
     génériques → core/, instances .tres de données propres à une feature →
     dans le dossier de cette feature (ex. entities/player/)

5. Input Map configuré : move_left, move_right, move_up, move_down
   (Project Settings → Input Map)
