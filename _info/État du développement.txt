PHASE 1 — MOUVEMENT + ATTAQUE
================================

[FAIT] Mouvement top-down + FSM Idle/Walk — testé et fonctionnel en éditeur

Détails techniques de ce qui est en place :

1. Player.tscn
   - Racine : CharacterBody2D (renommé "Player")
   - Enfants : AnimatedSprite2D, CollisionShape2D
   - Enfant StateMachine (Node, script state_machine.gd)
	 - Enfant Idle (Node, script idle_state.gd)
	 - Enfant Walk (Node, script walk_state.gd)
   - Les noms "Idle" et "Walk" doivent rester exacts (utilisés comme clés de
	 dictionnaire dans state_machine.gd)

2. Pattern State générique (réutilisable, pas juste pour Player)
   - scripts/core/state.gd → class_name State
	 Interface : enter(actor), exit(), physics_update(delta, actor),
	 handle_input(event, actor) — toutes vides/virtuelles dans la base
   - scripts/core/state_machine.gd → class_name StateMachine
	 - @export var actor: CharacterBody2D (assigné dans l'Inspecteur avec le
       noeud Player)
     - states: Dictionary rempli dans _ready() à partir des enfants
     - _physics_process délègue à current_state.physics_update()
     - transition_to(state_name) : exit() → swap current_state → enter()
   - Les états concrets accèdent à leur StateMachine parente via
     (get_parent() as StateMachine) — jugé sécuritaire car les states sont
	 garantis d'être des enfants directs d'une StateMachine par construction

3. États concrets du Player
   - scripts/entities/player/idle_state.gd
   - scripts/entities/player/walk_state.gd
   - Emplacement choisi : scripts/entities/ pour les states concrets liés à
     une entité précise (par opposition à scripts/core/ qui est générique).
     scenes/entities/ reste réservé aux ennemis/NPCs (pas le Player).

4. Vitesse en data-driven (pattern Resource du doc original, pas hardcodé)
   - scripts/core/movement_config.gd → class_name MovementConfig,
     @export var speed: float = 200.0
   - resources/data/player_movement_config.tres → instance de données
   - WalkState a @export var config: MovementConfig, assigné dans
	 l'Inspecteur avec le fichier .tres ci-dessus
   - Convention établie : scripts de classe Resource → scripts/core/,
	 fichiers .tres de données → resources/data/

5. Input Map configuré : move_left, move_right, move_up, move_down
   (Project Settings → Input Map)
